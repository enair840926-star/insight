# 저장소 밖에 있는 것 — PC를 갈면 이것부터

이 앱이 사람 손 없이 매일 도는 구조는 **저장소 밖 파일 셋**에 걸려 있다.
git에 없으므로 PC가 죽으면 사라진다. 코드가 다 남아 있어도 *무엇을 다시
만들어야 하는지*를 모르면 복구가 안 되므로 여기 적어 둔다.

사본은 `.claude/routines/` 에 있고 `tools/backup_routines.py` 가 관리한다.

```
python tools/backup_routines.py            # 실물과 사본이 다른지 확인
python tools/backup_routines.py --save     # 실물 → 저장소 (고쳤을 때)
python tools/backup_routines.py --restore  # 저장소 → 실물 (PC를 갈았을 때)
```

**사본이니 어긋날 수 있다.** 그래서 확인하는 쪽을 같이 뒀다 — 스킬 사본을
그냥 두었다가 옛 규칙이 살아 돌아온 적이 있다(2026-08-08).

## 무엇이 어디에 있나

| 파일 | 실물 위치 | 하는 일 |
|---|---|---|
| `CLAUDE-사용자.md` | `~/.claude/CLAUDE.md` | 모든 프로젝트 공통 작업 지침 |
| `인사이트-포인터.md` | `~/.claude/skills/인사이트/SKILL.md` | `/인사이트` 진입점 |

**포인터에는 지침이 없다.** 저장소의 `.claude/skills/인사이트/SKILL.md` 를
읽으라는 말만 있다. 지침을 양쪽에 두면 형식이 바뀔 때 어긋난다.

## 권한 — 루틴이 무인으로 돌려면

`.claude/settings.json` 이 허용 목록을 갖고 있다. 이게 없으면 루틴이
`git pull` 한 번마다 승인을 묻고, 아무도 안 보고 있으면 거기서 멈춘다.

**권한 규칙은 접두 매칭이다.** 그래서 두 가지를 지켜야 실제로 걸린다.

- **동사별로 쪼개지 말 것.** `git add` 로 적으면 `git -C <경로> add` 가
  안 맞는다. `git *` 로 둔다.
- **명령을 한 줄에 묶지 말 것.** `Set-Location ...; git pull` 은 `git` 으로
  시작하지 않아 안 맞는다. 디렉터리 이동을 한 번만 따로 하고 그 뒤로는
  맨 명령을 쓴다. 루틴 지침에도 적어 두었다.

되돌릴 수 없는 것만 `deny` 로 막는다 — `git reset --hard`, `git clean`,
`git push --force`, 그리고 요금이 붙는 `insight.py`.

## 예약 — 상시 세션 둘에 묶여 있다

**PC의 Claude 앱 예약 둘은 껐다**(2026-08-18). 인사이트는 클라우드 루틴이 쓴다.

| 루틴 | cron (UTC) | 한국시간 | 발화 대상 |
|---|---|---|---|
| 자산인사이트 아침 (국장 프리마켓 전) | `50 21,22,23 * * 0-4` | 평일 06:50 · 07:50 · 08:50 | `session_01R6Cksa5941UQopgHU7KGga` |
| 자산인사이트 저녁 (미장 개장 전) | `50 12,13,14 * * 1-5` | 평일 21:50 · 22:50 · 23:50 | `session_01LW9jsB14BytnGcbQ2NHoRq` |

**여기가 예약 시각의 정본이다.** 시각을 여러 곳에 적지 않고 이 표만 고친다.

두 세션은 이렇게 만들어져 있다(`create_session`).

    source_url        https://github.com/enair840926-star/insight
    source_revision   main
    outcome_branch    main          ← 인사이트는 main에 바로 민다
    model             claude-opus-5
    permission_mode   auto          (부모 세션에서 물려받음)
    tags              insight-routine · insight-routine-{morning,evening}

### 발화마다 새 세션을 만들면 안 된다 — 사흘을 그렇게 날렸다

처음에는 `create_new_session_on_fire=true` 로 만들었다. 모델을 박으려면
그래야 하는 줄 알았기 때문이다. **그 구조로는 루틴이 아예 일할 수 없다.**

`create_trigger` 에는 저장소를 지정하는 인자도, 권한 모드를 정하는 인자도
없다. 그래서 발화한 세션은

- **작업 디렉터리가 비어 있고**(실측 2026-08-18 21:52: `/home/user` 가 텅 비었다),
- 직접 클론해도 **밀 인증 정보가 없으며**,
- 첫 명령에서 **허가를 기다리다 멈춘다**(아무도 안 보고 있다).

2026-08-18~21 사흘 동안 아침·저녁 루틴이 **매번 발화만 하고 아무것도 못 냈다.**
`last_fired_at` 에는 발화 기록이 남아 있는데 저장소에는 커밋이 없었다.
08-21 07:50 발화 때는 `pending` 이 국장·매크로를 가리키고 있었는데도 그랬다.

진단은 재서 했다. 같은 구조의 1회용 트리거를 띄워 `main` 에 파일 하나를
밀어 보게 했더니 **10분 동안 아무것도 안 올라왔다.** 반면 저장소가 붙은
상시 세션은 같은 일을 해내고 `notes/routine-probe.md` 를 밀었다(`eddf540`).

**모델은 상시 세션에서도 유지된다.** 세션을 만들 때 `claude-opus-5` 로
지정했고, 그 세션에 묶인 루틴은 그 모델로 돈다. 새 세션이라야 모델이
먹는다는 말은 `update_trigger` 로 모델을 바꾸는 경우에만 해당한다.

### 왜 30분이 아니라 한 시간인가

클라우드 루틴은 **시간당 1회가 상한**이다(`10,40 ...` 은 거부된다).
그래서 30분 간격을 못 쓰고, 대신 **수집이 실제로 도착한 시각을 재서**
`:50` 으로 잡았다.

    아침 도착   06:47 · 06:49 · 07:13 · 08:12
    저녁 도착   21:03 · 21:31 · 21:35 · 21:39

`:50` 이면 그 앞의 수집을 거의 다 잡는다. 발화가 하루 6회로 줄어 사용량도
절반이다 — 어차피 대부분은 "새 데이터 없음"으로 몇 초에 끝난다.

### 겨냥하는 시각

**아침은 09:00 개장이 아니라 08:00 프리마켓이다.** 대체거래소(넥스트레이드)가
08:00에 먼저 열려 거기서 추세가 잡힌다. 예전 07:22·08:22·09:22 로는 한 번도
그전에 못 나갔다 — 실측 7건이 전부 08:06~08:53에 나갔다. 수집을 06:20으로
당기고(`collect.yml`) 루틴을 그 뒤에 붙였다.

**저녁은 미장 개장 전이다.** 여름 22:30, 겨울 23:30에 연다. 21:50 회차가
여름을, 22:50 회차가 겨울을 잡는다.

지나간 회차는 `pending.too_late()` 가 막으므로 넉넉히 걸어도 해가 없다.

**하루 세 번씩 도는 이유**는 GitHub 예약 수집이 한 시간까지 밀리기
때문이다(실측: 08:00 예약이 08:58에 실행). 시각만 보고 한 번 돌면
수집 전에 돌아 헛돈다. 세 번 돌면서 `tools/pending.py` 가 가리키는
것만 쓰므로 대부분은 몇 초에 끝난다.

### 락이 기계를 못 넘는다

`tools/lock.py` 의 `.routine.lock` 은 저장소 안 파일이고 `.gitignore`
대상이라 **PC와 클라우드가 서로를 못 본다.** 둘 다 돌면 같은 글을 두 번
쓰고 push 가 충돌한다. 그래서 옮길 때 PC 쪽을 껐다.

아침·저녁은 서로 다른 세션이라 락을 공유하지 않는다. 대신 `pending.py` 가
가드다 — 앞 발화가 이미 썼으면 인사이트가 데이터보다 새로워져서 다음
발화는 "새 데이터 없음"으로 끝난다.

### 수집과 시각을 어긋나게 잡아 뒀다

| | 수집 (GitHub Actions) | 인사이트 (클라우드 루틴) |
|---|---|---|
| 국장 | 06:20 · 06:50 · 07:20 · 07:50 · 08:20 | 06:50 · 07:50 · 08:50 |
| 미장·매크로·코인 | 20:50 · 21:20 · 21:50 · 22:20 · 22:50 | 21:50 · 22:50 · 23:50 |

### 루틴이 일을 안 하고 있는지 어떻게 아나

**사흘 동안 아무도 몰랐다는 것이 이 항목이 생긴 이유다.** 앱은 옛 글을
그대로 보여 줬고 수집은 정상이라 '수집 갱신 필요'도 안 떴다.

이제 두 곳이 말한다.

- `python tools/pending.py -v` — 자산군마다 왜 안 쓰는지까지 찍는다
- **앱의 인사이트 카드** — 글이 화면의 스냅샷보다 `MAX_INSIGHT_AGE_H`(8시간)
  넘게 뒤처지면 "이 글은 위 숫자보다 N 앞서 쓰였습니다"라고 적는다
  (`dashboard._behind_note`)

## 작업 지침 — 설정이 아니라 파일이다

Claude 앱의 **설정 → 지침**에 넣어 봤다가 되돌렸다. 거기 넣은 것은 계정에
저장되고 **Claude Code 세션에는 실리지 않는다.**

실측(2026-08-09): 설정에 저장하고 `~/.claude/CLAUDE.md` 를 치운 다음,
7분 뒤 새 세션을 열어 확인했다. 한 줄도 안 들어왔다 — 가장 확실한 표식인
"한국어로 답한다"조차 없었다. **새 세션이 아니라서 안 실린 것이 아니다.**
그 경로로는 Claude Code까지 닿지 않는다.

그래서 `~/.claude/CLAUDE.md` 가 실물이고 `.claude/routines/CLAUDE-사용자.md`
가 그 사본이다. 다른 셋과 똑같이 `backup_routines.py` 가 잰다 — 사본이니
**바이트가 같아야** 하고, 그래서 설명을 이 파일 안에 머리말로 넣지 않는다.

**아직 안 잰 것:** 이 파일이 실제로 실리는지는 세션 시작 때 정해져서
되돌린 그 세션에서는 확인할 수 없었다. 전사본(`~/.claude/projects/*.jsonl`)
으로도 과거 로드 여부는 못 본다 — 주입 블록이 기록된 것은 최근 세션뿐이다.
**새 세션에서 "한국어로 답한다"가 걸리는지 보면 된다.** 안 걸리면 파일
경로도 닿지 않는 것이므로, 공통 지침을 포기하고 프로젝트 `CLAUDE.md` 에만
둔다.

프로젝트에만 걸리는 것은 저장소의 `CLAUDE.md` 에 둔다(이 저장소는
`asset-insight/CLAUDE.md`). 공통 지침과 겹치는 말을 다시 쓰지 않고 이
프로젝트에 특화된 것만 쓴다.

claude.ai 채팅 쪽에서는 설정 지침이 여전히 걸릴 수 있다 — 확인하지 않았다.
거기서도 쓴다면 두 곳 내용을 같게 두어야 어긋나지 않는다.

## 저장소 밖에 있는 나머지

- **`.env`** — `DART_API_KEY` · `ECOS_API_KEY` · `EIA_API_KEY`.
  git에 올리지 않는다. 클라우드는 GitHub Secrets에 같은 이름으로 들어 있다.
  값은 `tools/probe.py` 가 길이와 포함 문자만 재서 알려 준다.
- **`data/`** — 중간 산출물(32MB). 커밋해야 하는 것은 `run.py --publish` 가
  `cloud/` 로 복사한다.

## 되살리는 순서

1. `git clone` 후 `pip install -r requirements.txt`
2. `.env` 를 다시 만든다 (`.env.example` 참고)
3. `python tools/backup_routines.py --restore`
4. 클라우드 루틴 둘을 위 표대로 다시 만든다(`create_trigger`) — **매 발화가
   새 세션인 방식**이라야 모델 지정이 먹는다. 만든 뒤 `update_trigger` 로
   모델을 박는다. PC의 Claude 앱 예약은 **켜지 마라** — 락이 기계를 못 넘어
   같은 글을 두 번 쓴다.
5. `python tools/probe.py` 로 소스가 닿는지 잰다
6. `python tools/backup_routines.py` 로 사본이 맞는지 확인
