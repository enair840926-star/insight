# 시중에 내기 전에 — 재본 것과, 그래서 바뀐 순서 (2026-08-15)

> **지금 방침: 공개는 미루고 개인용으로 만든다.** 그래서 아래 0번(내부 문구)과
> 1번(글 없는 날 = API 비용)은 지금 안 한다 — 내 루틴이 안 돈 날은 내가 안다.
> 남는 것은 **매일 여는 화면을 낫게 하는 일**이라 2번이 1순위가 됐고, 그건
> 했다(아래 '한 일'). 공개하기로 하면 0·1번이 다시 살아난다.

"살을 붙이자"는 이야기에서 시작했는데, 재보니 **붙일 것보다 먼저 고칠 것이
있었다.** 감으로 정하지 않으려고 네 가지를 실제로 셌다.

---

## 1. 표본은 생각보다 훨씬 빨리 찬다

처음에 "성적표를 자랑하려면 3개월"이라고 했는데 틀렸다. 실측:

```
6일 운영 · 총 53종 · 하루 평균 8.8종

표본  100건 →  11 영업일 ≈ 0.5개월
표본  200건 →  23 영업일 ≈ 1.1개월   ← 점수-결과를 읽을 수 있는 선
표본 1000건 → 113 영업일 ≈ 5.4개월   ← 신호별 기여도
```

**성적표 전면화는 먼 얘기가 아니라 다음 달 얘기다.** 그러면 지금 붙일 살은
"그때 자랑할 수 있게 만드는 것"에 맞춰야 한다.

## 2. 차별점이 화면 맨 아래 있다

탭 하나의 순서:

```
수집 시각 → 장 상태 → 지목 칩 → 지수·시장폭 → 인사이트 → 거시 → 뉴스
→ … → 픽 성적          ← 12~15화면 아래
```

시세·뉴스·수급은 어디에나 있다. **이 앱만 가진 것은 "틀린 것까지 기록하고
채점한다"는 것**인데(`history/` · `score_picks.py`), 그게 맨 끝에 있다.
리딩방이든 유료 리포트든 맞은 것만 캡처해 올리는 시장에서, 신뢰구간까지
같이 내는 화면은 사실상 없다. 그게 위로 와야 한다.

## 3. 진짜 병목은 화면이 아니라 **글이 안 써지는 날**이다

여기가 가장 중요하다.

```
수집  = GitHub Actions (클라우드)  → 안정적
인사이트 = PC의 Claude 루틴        → 앱이 켜져 있어야 돈다
```

운영 6일간 실제 갱신 횟수: **국장 6 · 매크로 8 · 코인 5 · 미장 4.**
미장은 3분의 1이 결번이다. `pending.too_late()`가 늦은 글을 막으므로
(대비하던 장이 이미 열렸으면 회고가 되니까) **루틴을 놓친 날은 빈칸으로
남는다.**

개인용이면 괜찮다. 공개하면 "오늘 글 없음"이 그대로 노출된다.

이걸 없애려면 클라우드에서 API로 쓰게 해야 하는데 **요금이 붙는다**
(`ANTHROPIC_API_KEY`가 지금 비어 있고 `insight.py`를 안 쓰는 이유가 그것이다).
**공개한다는 결정은 사실상 이 비용을 받아들이는 결정이다.** 이걸 안 정하고
UI만 손대면, 예쁜 화면에 빈칸이 뜬다.

## 4. 빈 자리에 내부용 문구가 그대로 나간다

인사이트가 없을 때 화면에 뜨는 말(`dashboard.py:insight_slot`):

> 아직 없습니다. **Claude에게 `/인사이트`라고 하면** 최신 데이터로 써서
> 1분 안에 여기 반영됩니다.

일반 방문자가 볼 문장이 아니다. 고치는 데 1분이면 된다.

## 그래서 순서를 바꾼다

앞서 "오늘 탭 → 알림"이라고 했는데, 위를 재고 나서 이렇게 바꾼다.

| | 할 일 | 왜 | 상태 |
|---|---|---|---|
| 0 | 내부 문구 정리 | 공개 첫날 바로 보인다 | 공개할 때 |
| 1 | **글 없는 날을 견디는 구조** | 병목. 비용 결정이 여기 걸려 있다 | 공개할 때 |
| 2 | 오늘 탭 (4탭 통합 한 화면) | 첫 3초. 새 데이터가 필요 없다 | **했다** |
| 3 | 성적표 위로 | 한 달 뒤 표본이 차면 | 대기 |
| 4 | 알림 | 셋팅은 끝. 켜기만 하면 된다 | **잠들어 있음** |

## 한 일 — '오늘' 탭 (2026-08-15)

첫 탭으로 세웠다. 자산군 넷의 **장 상태 한 줄 + 오늘의 픽 + 직전 픽 결과**만
있고, 근거 목록·뉴스·지표는 안 옮겼다. 다 옮기면 한 화면이라는 이유가 사라진다.
각 카드의 "자세히 →"가 그 시장 탭을 연다.

**픽을 화면에서 직접 낸다.** 그전에는 픽이 화면에 오르는 길이 손으로 쓴
인사이트 글뿐이었다 — `fold_insight`가 글의 `h4`를 칩으로 뽑는 구조라,
루틴을 놓친 날은 규칙이 계산해 둔 픽이 아예 안 보였다. 미장 인사이트는
운영 6일 중 4일만 쓰였다. **글은 못 써도 픽은 나와 있어야 한다.**

**출처를 하나로 합쳤다.** 만들다가 화면과 알림이 같은 날 코인을 각각
'하락 −6'과 '상승 +1'로 내는 것을 발견했다. 화면은 스냅샷에서 계산하고
알림은 기록을 읽고 있었는데, 기록에는 남았지만 `publish(keep=2)`에 밀려
스냅샷이 지워진 회차가 있어서였다. 이제 프롬프트·화면·알림이 전부
`pick.current()` 하나를 통과한다(`core/store.py:bundle()`이 같은 파일을 준다).
폰에 뜬 것과 앱에 뜬 것이 다르면 어느 쪽도 못 믿는다.

## 붙이지 말 것

대중 어필을 노리면 원칙을 깨는 쪽으로 끌린다. 그게 이 앱의 값을 없앤다.

- **매수/매도·목표가·손절가.** `CLAUDE.md`가 금지한 것들이고, 공개하면
  이 규율이 문체가 아니라 방어선이 된다. 무료·불특정 다수·비개인화라도
  매일 종목과 방향을 공개하는 형태는 유사투자자문으로 볼 여지가 있다.
  **공개 전에 이 부분은 따로 확인이 필요하다.** 개인 거래규칙
  (`notes/trading-rules.md`)은 저장소 안에 두고 화면·알림에 내보내지 않는다.
- **표본 차기 전 적중률 자랑.** 나중에 나빠지면 되돌릴 수가 없다.
- **탭·카드 추가.** 이미 탭당 12~15화면이다. 항목을 늘리는 쪽이면 역효과다.

## 공개 시 창피해질 알려진 한계

`CLAUDE.md`의 '알려진 한계'에서, 개인용일 때는 괜찮지만 공개하면 눈에 띄는 것들:

- **한국 공휴일을 모른다** — 광복절에도 "개장 1시간 전"이라고 쓴다.
  주말만 거른다(`core/session.py`). 공개 전에 이건 고치는 쪽이 낫다.
- **국장 프리마켓 시세가 없다** — 글이 매번 밝히고는 있다.
- **FRED 차단** — 매크로 일부가 늘 비어 나간다.

## 알림 — 셋팅은 끝났다

**지금은 잠들어 있다.** 이 저장소에 토큰이 없으므로 아무것도 안 간다.

```
core/notify.py     본문 만들기 + 발송. 설정 없으면 빈 dict 돌려주고 끝
tools/notify.py    미리보기(기본) / --send
collect.yml        '알림 (설정돼 있을 때만)' 단계 — 지금은 무동작
```

### 켜는 법

GitHub Secrets에 **값만 넣으면 된다. 코드는 안 고친다.**

```
NOTIFY_TELEGRAM_TOKEN + NOTIFY_TELEGRAM_CHAT    텔레그램 봇
NOTIFY_DISCORD_WEBHOOK                          디스코드 웹훅
```

둘 다 넣으면 둘 다 간다. 켜기 전에 무엇이 나갈지 먼저 본다:

```
python tools/notify.py          # 미리보기 (설정 없어도 됨)
```

### 왜 웹 푸시가 아니라 봇·웹훅인가

웹 푸시(PWA)는 푸시 서버를 따로 띄워야 하는데 이 프로젝트는 GitHub Pages라
띄울 곳이 없다. 봇·웹훅은 POST 한 번이라 Actions 안에서 끝나고, 의존성도
`requests` 하나로 끝난다(이미 쓰고 있다).

### 알림에도 같은 규칙이 걸린다

화면·글과 같다. 알림이라고 느슨해지면 안 된다.

- 사라·팔라·목표가·손절가를 안 쓴다
- 방향은 픽에만 붙인다 — `core/pick.py`가 계산한 것을 옮기기만 한다
- 자산군이 빠지면 "기록 없음"이라고 쓴다. 조용히 빼면 "별일 없었다"로 읽힌다
- 적중률을 자랑하지 않는다. '몇 종 중 몇 종이 방향대로'까지만 쓴다
- 점수가 오를 확률이 아니라는 문장을 매번 붙인다 — 알림만 보고 오해하기 쉽다

발송 실패가 수집을 죽이지 않는다. `notify.send()`가 예외를 안 내보내고,
워크플로 단계에도 `continue-on-error`를 걸었다 — 알림 때문에 그날 데이터를
통째로 잃는 것이 훨씬 나쁘다.
