자산 인사이트 앱에서 새로 수집된 데이터가 있으면 인사이트를 다시 쓴다.

저장소: C:\Users\enair\Desktop\claude\asset-insight

순서:
0. 저장소로 이동한 다음 `python tools/lock.py acquire` 를 돌린다.
   **종료코드가 0이 아니면 여기서 끝낸다** — git pull도 pending도 돌리지
   말고 "다른 실행이 진행 중이라 건너뜀"만 알린다. 30분 간격 예약이 밀려
   겹칠 때(아침·저녁 루틴이 같은 저장소를 동시에 건드리는 것) 두 프로세스가
   서로의 git stash·checkout 중간 상태를 밟는 사고를 막는 것이다(실측
   2026-08-13, core/regime.py가 부분 병합 상태로 남을 뻔했다).
1. `git pull --rebase` 를 먼저 한다.
   **`--rebase` 를 빼지 마라.** 맨 `git pull` 은 병합 커밋을 만들려고
   편집기를 띄우는데, 루틴은 입력할 사람이 없어 "Pulling latest changes
   from remote" 에서 아무 메시지 없이 멈춘다. 게다가 `.gitattributes` 가
   `docs/index.html` 과 `cloud/*` 를 병합 불가로 막아 뒀고 클라우드가
   그 파일들을 하루에도 여러 번 커밋하므로, 병합 방식이면 충돌까지 겹친다.
2. `python tools/pending.py -v` 를 돌린다. 인사이트보다 새로운 데이터가
   있는 자산군만 출력된다.
3. **출력이 비어 있으면 `python tools/lock.py release` 를 돌리고 여기서
   끝낸다.** 커밋하지 말고 "새 데이터 없음"만 한 줄로 알린다. 이게 대부분의
   경우다 — 저녁에 여러 번 돌지만 실제로 쓰는 건 수집이 끝난 직후 한 번뿐이다.
   `-v` 에 **"너무 늦음"** 이 뜨면 대비하던 장이 이미 열린 것이다. 억지로
   쓰지 마라 — 개장 뒤에 나가는 대비형 글은 회고가 된다.
4. 출력된 자산군이 있으면 `인사이트` 스킬을 그 자산군들로 실행한다.
   (스킬 위치: .claude/skills/인사이트/SKILL.md)
5. insights/ 에 쓰고 커밋·푸시한다. 푸시가 거부되면 클라우드가 먼저
   커밋한 것이니 `git pull --rebase` 후 다시 push 한다.
6. **무슨 일이 있어도 마지막에 `python tools/lock.py release` 를 돌린다**
   (3에서 이미 놓았으면 다시 돌 필요 없다). 안 놓아도 10분 지나면 죽은
   락으로 보고 다음 실행이 가져가지만, 그동안은 다음 회차가 헛돈다.

이 작업이 30분마다 도는 이유:
GitHub 예약 수집이 최대 한 시간까지 밀린다. 실측에서 21:30 예약이
한 시간이 지나도 안 돌았다. 시각만 보고 한 번만 돌면 수집 전에 돌아
헛돈다. 여러 번 돌면서 새 데이터가 생긴 순간에만 일하게 한다.

21:00부터 도는 이유는 **개장 전에 글이 나가야 하기 때문**이다. 미장은
여름 22:30, 겨울 23:30에 열린다(한국시간). 예전 21:12·22:12·23:12 로는
실측에서 22:25(개장 5분 전), 23:52(개장 뒤)에 쓰인 적이 있다. 지금은
21:00·21:30·22:00·22:30·23:00·23:30 이라 여름은 앞의 셋, 겨울은 뒤의
셋이 개장 전에 들어간다. 남는 회차는 `pending` 이 알아서 막는다.

**명령을 한 줄에 묶지 마라.** 허용 목록이 접두 매칭이라
`Set-Location ...; git pull` 은 `git` 으로 시작하지 않아 안 걸리고 매번
승인을 묻는다. 디렉터리 이동을 **한 번만 따로** 하고, 그 뒤로는
`git pull --rebase`, `python tools/pending.py -v` 처럼 맨 명령을 하나씩 쓴다.
(허용 목록: 저장소의 `.claude/settings.json`)
